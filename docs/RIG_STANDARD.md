# Единый скелет (риг) — простыми словами

## Зачем это

У каждой скачанной модели свой скелет с разными именами костей. Из-за этого:
- в Cascadeur анимация «разваливается»;
- Unity не понимает, где рука, а где нога;
- анимацию с одной модели нельзя перенести на другую.

Решение — **один стандартный скелет для biped-персонажей** (Unity Humanoid).
Четвероногие — **отдельный** шаблон (не этот список).  
Полный конвейер: [`ANIMATION_CANON.md`](./ANIMATION_CANON.md).

Имена костей — как ждёт Unity («Humanoid»), поэтому модель подхватывается
движком без переделок.

## Как Вью с этим помогает

1. **`rig_check`** — смотрит скелет модели (из живого Blender, из `.blend`
   файла или по списку костей) и сравнивает со стандартом: какие кости есть,
   каких обязательных не хватает, что как переименовать.
2. **`rig_apply`** — переименовывает кости в запущенном Blender по плану.
3. **`rig_standard`** — показывает сам стандартный скелет.

Вью **узнаёт кости, даже если они названы по-разному** — понимает Mixamo
(`mixamorig:LeftArm`), Rigify (`upper_arm.L`), обычные `Foot.L`, и даже
транслитерацию с русского (`Bedro`, `Golen`, `Kist`).

## Стандартный скелет (biped)

Обязательные кости помечены ✱ (без них Unity не соберёт «Humanoid»).

После **переименования** костей веса обычно сохраняются.  
После **нового бинда** (AccuRIG) — авто-веса; ручная карта не с нуля
(см. `ANIMATION_CANON.md`).

```
✱ Hips            (таз — корень скелета)
✱ Spine           (позвоночник)
  Chest           (грудь)
  UpperChest      (верх груди)
  Neck            (шея)
✱ Head            (голова)
  Left/Right Shoulder    (ключица)
✱ Left/Right UpperArm    (плечо)
✱ Left/Right LowerArm    (предплечье)
✱ Left/Right Hand        (кисть)
✱ Left/Right UpperLeg    (бедро)
✱ Left/Right LowerLeg    (голень)
✱ Left/Right Foot        (стопа)
  Left/Right Toes        (пальцы ноги)
```

## Пример работы (реальный прогон)

Модель со скелетом Mixamo → Вью сверила со стандартом → предложила план →
переименовала. Было `mixamorig:LeftArm` → стало `LeftUpperArm` и т.д.

```
Скелет ДО:    mixamorig:Hips, mixamorig:LeftArm, mixamorig:LeftUpLeg, ...
Скелет ПОСЛЕ: Hips, LeftUpperArm, LeftUpperLeg, ...
```

## Как пользоваться

При открытом Blender с моделью:

```bash
python -m viu run "Проверь скелет модели и приведи его к стандарту"
```

Или без Blender, по файлу (нужен путь к blender.exe в `VIU_BLENDER_EXE`):

```bash
python -m viu run "Проверь скелет в u:\Anabarra\Blender_Files\shanya.blend"
```

## Важно

- Переименование меняет **только имена** костей — форму и вес не трогает.
  Это безопасный первый шаг унификации.
- Если у моделей **разное строение** скелета (например, лишние/недостающие
  кости, другое число позвонков), одного переименования мало — тогда нужен
  полноценный перенос (retarget). Это следующий уровень, сделаем при
  необходимости.

## Два подхода: переименование или карта (важно!)

Скелеты бывают двух видов, и подход разный:

- **Простой скелет** (у каждой кости «человеческое» имя) — Вью переименовывает
  кости к стандарту (`rig_check` → `rig_apply`).
- **Сложный риг (Rigify и подобные)** — сотни служебных костей (`DEF-`, `ORG-`,
  `MCH-`, `tweak_`, `WGT-`…). Их **нельзя** переименовывать — риг сломается.
  Вместо этого Вью строит **карту**: слот Unity Humanoid → нужная деформирующая
  кость (`DEF-…`). Карта подтверждается в Unity (настройка Avatar). Инструмент —
  `rig_map`; а `rig_check` сам определяет тип рига и выбирает правильный путь.

Проверено на реальной модели (Rigify, 827 костей) — карта построилась целиком:

```
Hips → DEF-spine   Spine → DEF-spine.001   …   Head → DEF-spine.006
LeftUpperArm → DEF-upper_arm.L   LeftHand → DEF-hand.L   LeftFoot → DEF-foot.L
```
