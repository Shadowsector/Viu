# Вью: концепция (2026)

Документ для Дена — не ТЗ на год, а **складная модель**, куда всё должно сходиться.
Старые кнопки и идеи не выбрасываем; **упрощаем путь пользователя**.

---

## Одна фраза

**Вью — соавтор Анабарры:** принимает один asset за раз, готовит его к игре, помнит контекст, не тонет в сотнях файлов на диске.

---

## Три папки на U: (единственное, что нужно помнить)

| Папка | Роль |
|-------|------|
| **`U:\Viu`** | Программа, `.viu` (память, каталог), **`Inbox`** — один пак на вход |
| **`U:\Anabarra`** | Игра: Unity, Library, Processed, Animations |
| **`U:\Desktop Mascot`** | Архив — **Вью не сканирует**. Оттуда копируешь **одну** папку в Inbox |

Вью **не ходит на C:\Downloads**, пока ты сам не переопределишь путь.

---

## Один pipeline для ассетов (вместо пяти кнопок)

```
Desktop Mascot  ──(ты копируешь один пак)──►  U:\Viu\Inbox
                                                    │
                    [Принять asset] ◄───────────────┘
                            │
         relink textures → pack → скрыть землю → Processed
                            │
                    Blender открыт ──► ты доводишь меши
                            │
                    [Разметить предметы] ──► каталог + affordances
                            │
                    Unity (prefab / оверлей) ──► игра
```

**Одна главная кнопка в Blender:** «**Принять asset**».  
«Разобрать Inbox» убрана из панели — её работу делает «Принять asset» (Inbox **или** уже лежащий blend в Library).

---

## Слои внутри одного .blend (домик, сарай)

| Слой | Имена в Blender | В игре |
|------|-----------------|--------|
| **Shell** | `Shell_Wall`, `Shell_Floor` | оболочка, не «сидеть на комнате» |
| **Interactive** | `Interactive_Bed`, `Interactive_Door` | вес, sit, open… |
| **Decor** | `Decor_Lamp` | фон |
| **Background** | Ground, Terrain… | скрывается при prepare |

Вью: карточка **на каждый меш**; Shell — одна кнопка «без разметки».

---

## Две «ноги» Вью

### 1. Автопилот (кнопки без LLM)

Быстро, предсказуемо, без API:

- **Принять asset** — Blender headless + pack
- **Разметить предметы** — GUI каталога
- **Обновить аниматор / Оверлей** — Unity
- **Что делаем дальше?** — агент смотрит roadmap

### 2. Ассистент (чат + мост Blender)

Когда Blender **открыт** с add-on:

- «переименуй все меши стен в Shell_»
- «удали коллекцию Environment»
- «покажи сокеты»

**Следующий шаг развития:** команды `prepare_step_*` в add-on (relink, hide_bg, pack) — те же шаги, но **в живом Blender** с отчётом в чат. Headless остаётся для кнопки «Принять asset».

## Потенциал (честно)

| Сильно | Слабо пока |
|--------|------------|
| Прозрачный pipeline Inbox → Processed | UV-bake в атлас |
| Каталог мешей + affordances | Полностью автоматический «вырезать фон» |
| Unity overlay, анимации, deploy | Интерактивный мастер без Blender |
| Память, roadmap, autopilot | Desktop Mascot bulk import (намеренно нет) |

**Игра интересная получится**, если не пытаться сделать из Вью «Total Commander + Blender + Unity в одной кнопке», а держать **узкий контракт:** один asset → готовый prefab домика / prop.

---

## Ближайшие шаги (технически)

1. ✅ «Принять asset» — Inbox **или** Library, поиск blender.exe, repair textures  
2. Add-on: `relink_textures`, `hide_background`, `pack_blend` (дублируют headless для чата)  
3. После разметки — экспорт FBX в `Assets/Props/` (одна кнопка)  
4. Домик → `Socket_Home` в Unity, смена prefab при апгрейде

## Для твоего сарайчика прямо сейчас

1. Задай **`VIU_BLENDER_EXE`** (если ещё не задан)  
2. Если textures в `Library\References\images\textures` — «**Принять asset**» **вернёт их рядом** с blend и перепривяжет  
3. Откроется `Old Stables_prepared.blend` — доведи, сохрани  
4. «**Разметить предметы**»
