# Монстры: что делать по шагам

Обновление Вью тянет ветку **`cursor/viu-agent-core-65c2`**.  
Каталог существ туда уже влит — после «Обновить Вью» перезапусти окно.

---

## Зачем это

Много скачанных моделей → привести к **нескольким размерам**.  
Тогда анимации пишутся **на размер** (гоблин-класс, волк-класс…), а не на каждого монстра отдельно.

Внутри класса рост чуть плавает (узкий допуск), lineup в Blender показывает всех **рядом с Шаней**.

---

## Почему «в папке 66», а скан говорит 103

Это нормально, не баг.

Скан считает **каждый файл модели**, а не «каждую папку»:

- форматы: `.fbx`, `.blend`, `.glb`, `.gltf`, `.obj`
- обход **рекурсивный** (подпапки тоже)
- плюс вторая корзина: `Lab/Models/Inbox` (если там что-то лежит)

Пример: папка `Goblin_A/` с файлами `Goblin.fbx` + `Goblin.blend` + `Goblin_LOD.fbx` → **три** записи в каталоге.  
66 папок легко дают ~100 файлов.

После следующего `creature_catalog_scan` в ответе будет разбивка: сколько файлов из какой папки.

Дубликаты одного персонажа (fbx и blend) потом можно пометить `skip` или просто размечать один «главный» файл — пока это не срочно.

---

## Важно: блендшейпы / morphs (уши, хвосты, гениталии)

У многих моделей есть **shape keys** (в Blender) / morph targets:

- уши прижать / поднять
- хвост вилять / свернуть
- половой орган **спрятан в теле** и morph'ом вытягивается / разворачивается

**Правило на весь пайплайн:**

1. **Не apply** modifiers «навсегда», если они убивают shape keys.
2. **Не bake** mesh в «плоский» объект без morphs, пока не решим, какие ключи оставляем.
3. Lineup сейчас делает только: импорт → scale корня → расставить в ряд. Morphs **не трогает**.
4. В каталоге у каждой записи по умолчанию `preserve_morphs=true`. Позже можно писать в `morph_notes`, что именно нашли глазами (`penis_reveal`, `ears`, `tail`…).

Когда дойдём до нормализации/prefab — сначала инвентаризация morphs, потом аккуратная обработка. Визионерские находки не выкидываем.

## Шаг 2. Следующий шаг прямо сейчас — разметка размера

Скан **не угадывает** рост. Он только список.  
Твоя работа: сказать каждому монстру «ты гоблин» / «ты волк» / «ты рядом с Шаней».

### 2a. Открыть очередь

В чат Вью **одной строкой**:

```
очередь существ
```

или:

```
creature_catalog_show mode=pending
```

Получишь список вроде:

```
[new] GreenGoblin | ? | biped | — | GreenGoblin.fbx  id=a1b2c3d4…
[new] DireWolf | ? | quadruped | — | DireWolf.blend  id=…
```

Справа у каждой строки есть `id=…` — короткий код записи.  
Имя файла тоже видно — по нему обычно понятно, кто это.

### 2b. Назначить класс одной модели

Смотришь на имя (или открываешь модель глазами в Blender/просмотрщике) и решаешь:

| size | Простыми словами | Рост примерно |
|------|------------------|---------------|
| `mini` | фея, кроха | ~30 см |
| `small` | гоблин, имп | ~80 см |
| `humanoid` | как человек / Шаня | ~175 см |
| `large` | крупный орк/тролль | ~235 см |
| `huge` | хватает Шаню за талию | ~360 см |
| `quad_mini` | куница, барсук | ~30 см в холке |
| `quad_med` | собака, волк | ~75 см |
| `quad_large` | лошадь, корова | ~160 см |

И как ходит (`locomotion`):

- `biped` — на двух
- `quadruped` — на четырёх
- `amorph` — слизень
- `tentacle` — щупальца
- `mimic` — сундук-мимик
- `flyer` — летает

**Пример команды** (подставь свой `id` или `slug` из очереди):

```
creature_catalog_set_size id=a1b2c3d4 size=small locomotion=biped
```

или по имени файла (slug ≈ имя без расширения, нижний регистр):

```
creature_catalog_set_size slug=greengoblin size=small locomotion=biped
```

Если модель NSFW и хочешь пометить:

```
creature_catalog_set_size slug=orc_boss size=large locomotion=biped nsfw=1
```

Если одна болванка и «маленький», и «большой» вариант:

```
creature_catalog_set_size slug=goblin_a size=small size_alt=humanoid locomotion=biped
```

После команды Вью ответит `OK` и покажет `anim_bucket` вроде `small__biped` — это будущая «полка анимаций» для всех таких же.

Разметка через чат по одной — нудно на сотне; позже сделаем удобный GUI. Пока так.

## Шаг 3. Линейка роста рядом с Шаней (когда есть несколько размеченных)

Когда хотя бы несколько с `size_class`:

```
creature_lineup
```

или только гоблины:

```
creature_lineup size=small
```

Если Шаня не нашлась сама:

```
creature_lineup shanya_path=U:\путь\к\Shanya.fbx
```

**Что произойдёт:**
- Вью напишет файлы в  
  `U:\Anabarra\Library\Lab\Creatures\Lineup\`
  - `lineup_job.json` — список кого ставить
  - `viu_creature_lineup.py` — скрипт Blender
  - потом появится `creature_lineup.blend`

**Ты запускаешь Blender** (один раз):

```bat
blender --background --python "U:\Anabarra\Library\Lab\Creatures\Lineup\viu_creature_lineup.py" -- "U:\Anabarra\Library\Lab\Creatures\Lineup\lineup_job.json"
```

(путь к `blender.exe` — как у тебя в PATH или полный)

**Результат:** открой `creature_lineup.blend` — **Шаня слева**, монстры в ряд, каждый уже **подогнан к target своего класса**. Глазами проверь: кто выбивается → смени ему `size` (шаг 2) и lineup снова.

Lineup **не ломает** блендшейпы — только масштаб и позиция.

## Шпаргалка команд

| Команда | Зачем |
|---------|-------|
| `creature_catalog_scan` / `сканируй существ` | собрать таблицу из Inbox |
| `creature_catalog_show mode=pending` / `очередь существ` | кого ещё не разметил |

Список всех: `creature_catalog_show mode=all`
