# Студия анимаций и стенд моделей

> Что за анимации мы собираем, как устроено их производство («студия») и на чём мы
> смотрим моделей, прежде чем пускать их в дело.
> Состояние на **2026-10-23**.

---

## 0. Одной страницей

| | |
|---|---|
| **Что производим** | анимации для персонажей Анабарры: Вью, Шаня, NPC, существа |
| **Из чего** | библиотека HS2 (948 размеченных клипов), Mixamo / X Bot, собственные клипы на канон-риге |
| **Чем** | библиотека/Mixamo → Cascadeur (только полировка) → ретаргет на канон-риг → приёмка на стенде |
| **Где смотрим модели** | UE 5.8, проект **AnimLab**, уровень `L_Stand` |
| **Где смотрим клипы** | Unity, сцена **CharLab** (в разработке) |
| **Куда кладём новое** | `Inbox/animations/` — по одному FBX |
| **Что уже есть** | каталог 948 клипов, «островной» сет 221 клип, стенд из 13 персонажей |

Главный принцип: **сначала смотрим — потом чиним**. Ни одна модель и ни один клип
не выбрасываются из-за того, что «выглядит криво»: сначала фиксируется, что именно
сломано (поза, текстура, масштаб, веса) и где — в исходнике или в конвейере.

## 1. Inbox — одна дверь для всего нового

```
Inbox/
  animations/   Анимации FBX — по одной, Mixamo / Cascadeur export
  creatures/    Модели существ (.blend / .fbx / .glb)
  references/   Референсы: картинки и видео для MoCap и идей
  cascadeur/    Очередь Cascadeur (.fbx / .blend)
```

Три маршрута, одинаковых по смыслу — «положил файл, дальше система сама
предложит шаг»:

- **Референс** → `references/` → окно «Референсы» в ComfyUI;
- **Существо** → `creatures/` → Студия существ в Blender (подготовка → рост → FBX);
- **Анимация** → `animations/` → окно «Описать новые FBX» → каталог.

После разметки клип попадает в каталог и дальше в игру. Модель после разметки
попадает в очередь стенда и в каталог существ.

## 2. Какие анимации у нас есть и какие нужны

### 2.1 Три источника

| Источник | Объём | Что это |
|---|---|---|
| Библиотека HS2 (бандлы `abdata`) | **948** размечено в каталоге; дампнуто 1377, в графе переходов 1216 | основной массив: локомоция, быт, бои, позы |
| Mixamo / X Bot | ~30 клипов, из них 18 докачано в 2026-10-04 | лазанье, повороты, стрейф, прыжки, падения |
| Свои клипы | `Shanya_*` — 15 (idle ×4, run ×3, sit-idle ×4, walk, fall, sleep, yawn) | сняты на канон-риг Шани |

Имена HS2 — не «просто имена», у них есть грамматика (см. `anim_taxonomy.md`):

```
[ростовка] семья [_номер] [_сторона] [_фаза] [_компонент]
```

- **Ростовка `L` / `M` / `S`** — это рост девушки, а не вариант жеста. Высокая
  опирается на забор животом, низкая — грудью: сцена одна, контактная поза разная.
- **Фаза** — `_in` (вход), `_loop` (цикл), `_out` (выход), одиночный клип.
  Без фазы клип обычно цельный.
- **Сторона** — `_L` / `_R` для парных движений.

Семья — это один и тот же смысл в разных ростовках и фазах. Поэтому в каталоге
запись одна на семью, а не на каждое имя.

### 2.2 Статусы: триаж не переписывается

| Статус | Клипов | Значение |
|---|---|---|
| `game` | **293** | идёт в игру |
| `later` | **533** | отложено: быт, работа, разговоры — вернёмся |
| `reject` | **85** | тематически не нужно или битое |
| без статуса | 37 | ещё не смотрели |

`reject` — это не «удалить». Клип остаётся в каталоге с причиной; вернуть его =
сменить статус и перегенерировать семантику. Триаж ставит человек, машина его
не трогает.

### 2.3 «Островной» сет — то, что реально нужно игре

Из `game` собрано **221** клип по 11 категориям:

| Категория | Клипов | Категория | Клипов |
|---|---|---|---|
| бой | 66 | сон / лёжа | 17 |
| idle | 33 | жесты | 16 |
| локомоция | 32 | сесть | 11 |
| переходы | 19 | осмотреться | 10 |
| прыжки | 9 | лазанье | 4 |
| плавание | 4 | | |

Это не «всё, что есть», а минимальный связный набор: персонаж может пройти,
побежать, повернуть, присесть, сесть, лечь, прыгнуть, поплыть, подраться и
осмотреться — и всё это стыкуется между собой.

### 2.4 Стыковка: вход → цикл → выход

У каждого клипа размечены **поза на входе** и **поза на выходе**
(`stand`, `sit_chair`, `sit_floor`, `crouch`, `kneel`, `lie_*`, `hang`, `water`,
`air`, `all4`), фаза и наличие root-motion. Плюс матрица близости поз:
для каждого клипа — 8 ближайших кандидатов «до» и «после».

Поэтому переходы не выдумываются: `Rig_Jump_Land → Rig_Idle_Loop` (0.005),
`Rig_Jog → Sprint` (0.044), `Bow_attack_02 → Bow_down` (0.02) — это измеренные
стыки, а не «на глаз».

### 2.5 Чего нет (честный список пробелов)

- **Перевал через препятствие** (vault) — `Running_Jump` кроет частично;
- **Бросок предмета** — своего клипа нет;
- **Толкнуть / потянуть / открыть** — есть в `later`, надо досмотреть;
- **Усталость после бега** (руки на коленях) — нет;
- **Осмотреться сидя или лёжа** — есть только стоя;
- **Неко-специфика** (хвост, уши) — один клип.

Это список закупок для студии: то, что дешевле сделать самим, чем искать.

## 3. Студия: как рождается клип

### 3.1 Семь стадий

1. **Заявка.** Ситуация → категория в островном сете → просмотр кандидатов.
   Если подходящего нет — это заявка на новый клип, с описанием словами
   («пятится, оглядываясь через плечо»), а не именем файла.
2. **Референс.** `references/` — видео или картинки. Референс обязателен:
   без него получается «средне-анимационный» жест.
3. **Черновик.** Дешёвый источник: библиотека, Mixamo, ручные ключи в Blender.
   **Cascadeur — только полировка** уже живого клипа на чистом канон-теле.
   Video MoCap не блокер и не единственный источник скелета.
4. **Ретаргет.** Бипеды — один канон-риг (Unity Humanoid / UE IK Retargeter).
   Четвероногие — отдельный quad-шаблон. Слизни, хвосты, щупальца — не Humanoid:
   шейпы и вторичная анимация. «Один скелет на всех» — сознательно не делаем.
5. **Приёмка на стенде.** Клип играется на живой модели: цикл/один раз, скорость
   0.25–2×, покадрово. Смотрим: не скользят ли ноги (сверяем скорость клипа с
   фактической), нет ли провала в пол, выворота, спайка, клиппинга, «не того пола».
6. **Разметка.** Одна запись на клип, внутри — на каких моделях проверено:

   ```json
   {
     "tags": ["sitting"],
     "comment": "сейдза, руки на коленях",
     "verified_on": {
       "shanya": {"quality": "ok"},
       "ru":     {"quality": "broken", "note": "провал бёдер"}
     },
     "motion": {"speed_mps": 1.38, "cadence_hz": 1.9, "stride_m": 0.72}
   }
   ```

   «На Шане ок, на Ру битая» — легальное состояние, а не противоречие.
7. **Публикация.** Каталог → островной сет → граф переходов → игра. Отчёт Дену:
   что добавлено, что сломано, какие вопросы.

### 3.2 Кто что делает

| Роль | Задача |
|---|---|
| **Ден** | вкус и приёмка: что считать живым, что нет; статусы и комментарии |
| **Вью (агент)** | черновики, разметка, замеры, сборка отчётов, поиск пробелов |
| **Девин** | интеграция в игру, граф переходов, рантайм |
| **Cascadeur** | полировка готового клипа, не производство с нуля |

### 3.3 Правила, которые нельзя нарушать

- Канон-риг персонажа — **AccuRIG (GUI) + Unity Humanoid**. Blender-проход
  только сохраняющий: не перестраивать скелет, не снимать веса.
- Исходники, веса, материалы не удаляются. Любая обработка — в стейджинге.
- Геометрия персонажей не редактируется ради «чтобы влезло».
- Клип не выбрасывается, пока причина не сформулирована.
- План — это не результат. «Скрипт отработал» ≠ «в игре выглядит правильно»:
  критерий только глазами, на стенде.

## 4. Стенд моделей (UE 5.8, AnimLab)

### 4.1 Зачем он нужен

Персонажей много, и они из разных эпох и пайплайнов: HS2-дампы, Unity-проекты,
Lust, Desktop Mascot, `3D Models`, старые бэкапы. У них разные единицы, разные
позы, разные наборы текстур и разные скелеты. Пока не видно их рядом и в
натуральную величину — нельзя решить, кто годится, а кто нет.

Стенд отвечает на три вопроса сразу:

1. **Модель** — как она выглядит: одежда, хвост, уши, пропорции, «не та модель».
2. **Сборка** — есть ли текстуры, не вывернуты ли материалы, не отвалились ли веса.
3. **Масштаб** — сравнение роста с линейкой и соседями.

### 4.2 Как устроено

- Проект: `AnimLab` (UE 5.8). **Показ идёт в скомпилированном окне `-game`,
  не в редакторе** — так видно то, что увидит игрок.
- Уровень: `/Game/ModelReview/L_Stand`.
- Модели стоят **в ряд по оси Y** с шагом 300 см, лицом к камере.
- На фоне — вертикальная **линейка** (полосы 50–350 см), чтобы рост читался
  без подписей.
- Подписи — `TextRender` над каждым персонажем: номер и имя.
- Камера — **свободная**: WASD + мышь (обычный `ADefaultPawn` через GameModeBase),
  без «рельсов» и без блюпринт-андроида.
- Посадка на пол: по **костям стоп**, а не по габаритам меша — иначе мусорный
  кусок геометрии поднимает всю модель в воздух.
- Ориентация: модели этого пайплайна смотрят локально в −Y, поэтому
  `yaw = 270` разворачивает их к камере.

### 4.3 Как модель попадает на стенд (5 шагов)

1. **Вход.** `ModelReview/in/<slug>/` — `<slug>.fbx` + текстуры плоско рядом +
   `meta.json` (источник, рост, поза, проблемы).
2. **Текстуры.** Если FBX не ссылается на картинки (частый случай у Unity-дампов
   и Lust), материалы **пересобираются в Blender** в чистый `Image → Principled`
   и FBX выгружается заново с `path_mode="STRIP"`. В UE ничего не привязываем
   руками: UE импортирует только то, что прописано в FBX.
3. **Масштаб.** Правится трансформ корня (не геометрия), с реимпортом и сверкой
   числа костей, вершин и текстур. Правило: ошибки единиц чиним, настоящих
   гигантов не трогаем, спорное — помечаем и оставляем Дену.
4. **Импорт в UE.** Только в **свежую папку** `/Game/ModelReview2/<slug>`:
   UE не перепривязывает материалы при замене существующего ассета, и старые
   остаются белыми.
5. **Постановка.** Спавн, посадка по стопам, разворот к камере, подпись.

### 4.4 Что уже стоит

На стенде — ряд персонажей **S01–S13**. В проект импортировано 15:
`fat_dwarf`, `goblinman`, `humangirl`, `humanman`, `orc_man`, `draenei_male_1`,
`ahmed`, `9338033`, `9338033_animated`, `ada_wong`, `alexa`, `shanya`, `tauren1`,
`ru`, `alice` (последняя ещё не поставлена в ряд).

Очередь — **173 бипеда** со статусом «ready» из 224 размеченных (всего в
инвентаре 299 записей, 296 папок входа). Импорт идёт **волнами** по 8–10 моделей.

### 4.5 Что стенд уже показал

Стенд сработал ровно так, как задумано: проблемы стало видно, а не «вроде норм».

| Симптом | Причина | Статус |
|---|---|---|
| «все белые» | старый экспортёр терял связи материалов | вылечено: пересборка материалов в Blender, текстуры 100% |
| «вросли в землю» / «висят в небе» | посадка по габаритам меша, а не по стопам | вылечено: посадка по костям |
| `ru` висит в небе | в меше мусорный элемент на −1168 см | известно, лечится посадкой по костям |
| `alexa` 17 м | гигантский баунд (`min.y = −836`) | известно, выносится в сторону с предупреждением |
| Шаня белая | у исходника нет body-текстуры рядом | вопрос к исходнику, не к конвейеру |

Ни одна из этих моделей не отбракована: пока это **вопросы**, а не приговоры.

### 4.6 Ресурсный режим

Под AnimLab выделено 5 ГБ VRAM, машина общая с редактором Анабарры (там работает
Девин). Поэтому: импорт волнами, тяжёлые операции с пониженным приоритетом,
Blender-проход и UE-импорт не запускаются одновременно.

## 5. Стенд клипов (Unity, CharLab) — в разработке

Отдельная сцена `CharLab` — не игра и не выставка, а лабораторный стол:

- круглая площадка 3 м, нейтральный серый, ровный трёхточечный свет, turntable;
- камера: орбит + пресеты «полный рост / лицо / грудь / руки / ноги / спина»;
- каталог клипов: листание, поиск по имени, фильтры (категория, «непросмотренные»,
  SFW по умолчанию), скорость 0.25–2×, покадровый шаг, loop/once;
- аннотация на клип, тоглы тегов и качества (`OK` / `BROKEN` + подтип бага);
- замер скорости локомоции — чтобы ноги не скользили в игре;
- окно уезжает на второй монитор, рабочий остаётся свободным.

Статус: DRAFT (RFC-039). Стенд моделей в UE уже работает, стенд клипов — следующий.


## 7. Что дальше

1. Довести стенд моделей до 30–50 персонажей (волнами), подписи — по фактическим
   габаритам, `alexa` — отдельно с предупреждением.
2. Посадить `ru` по стопам, разобраться с текстурой тела Шани.
3. Комментарии к моделям **на стенде** (журнал решений) + кнопка выхода.
4. Запустить CharLab и прогнать по нему островной сет — 221 клип, с разметкой
   per-model.
5. Закрыть пробелы: vault, бросок, толкнуть/открыть, усталость, осмотр сидя/лёжа.
